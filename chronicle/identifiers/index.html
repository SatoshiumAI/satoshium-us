Chronicle · Identifiers

Chronicle Identifier Specification

Chronicle identifiers provide stable, permanent identity for canonical Chronicle Entries. The identifier should remain simple enough to endure changes in Event Type, schema, relationships, publication state, and historical interpretation.

Identity belongs to the Entry. Classification and other changing semantics belong in structured fields, not inside the identifier.

Canonical Identifier Form

CHR-YYYY-NNNN

Example: CHR-2026-0001

This structure carries only the minimum durable semantics needed for human readability and operational sequencing: Chronicle namespace, assignment year, and sequence number.

Identifier Namespace

CHR is the Chronicle Entry namespace. It distinguishes canonical Chronicle Entry identifiers from identifiers issued by other Suite systems.

Required

Year Component

The four-digit year records the year the Chronicle identifier is assigned. It does not represent Event Date unless assignment and occurrence happen in the same year.

Required

Sequence Structure

The sequence is numeric, zero-padded, and scoped to the identifier-assignment year. The initial production form uses four digits beginning with 0001.

Required

Semantic Restraint

Event Type, originating system, status, verification state, publication state, jurisdiction, and other mutable meanings should not be encoded into the identifier.

Required

Identifier Anatomy

CHR → Chronicle Entry namespace
2026 → Identifier assignment year
0001 → Annual sequence

The identifier describes identity, not historical interpretation.

Permanence Rule

Once assigned, a Chronicle Entry identifier is permanent.

The same identifier remains attached to the Entry across corrections, new Versions, changes in Event Type classification, additional Relationships, Verification updates, publication changes, and preservation-state changes.

Entry identity persists even when Entry content evolves.

Reuse Prohibition

A Chronicle identifier must never be reassigned to a different Entry.

If an Entry is withdrawn, superseded, corrected, unpublished, or later determined to have been created in error, its identifier remains historically reserved.

Assigned once → Reserved forever

Corrections

A Correction does not create a new Chronicle Entry identifier when the underlying canonical Entry remains the same historical record.

Versions

Record Version changes occur beneath the stable Entry identifier. Version should be represented through explicit Version fields or related Version records, not by changing the canonical identifier.

New Occurrences

A genuinely distinct qualifying Occurrence receives a new Chronicle Entry and therefore a new identifier, even when it concerns the same external authoritative object.

Duplicate Entry Resolution

If two Entries are later determined to represent the same Occurrence, identifiers should not be recycled. Chronicle should preserve the identity history and resolve duplication through status, relationships, correction, or supersession procedures.

Identifier and Event Type

Event Type is required Entry classification, but it is not part of the identifier.

Identifier → Stable identity
Event Type → Governed classification

An Entry may be reclassified without changing its identifier if Chronicle later corrects or refines the Event Type.

Why Event Type Is Not Encoded

Encoding Event Type into identifiers would make identity dependent on taxonomy. If classification later changed, Chronicle would face a choice between changing a permanent identifier or preserving an inaccurate semantic code.

Stable identity should survive changing classification.

Identifier Assignment Year

The year component refers to the year the Chronicle identifier is assigned, not necessarily the year the historical Occurrence happened.

This is required for retrospective preservation.

Event Date may be 2025.
Chronicle Entry may be created in 2026.
Identifier may therefore be CHR-2026-0001.

Sequence Rule

Sequence numbers should be issued monotonically within each assignment year. Gaps are permitted when identifiers have been reserved or voided; gaps should not be closed through reuse.

Sequence continuity is desirable. Identifier permanence is mandatory.

Relationship to Other Suite Identifiers

Chronicle Entry identifiers remain independent from Certifier, Registry, Anchor, Beacon, Attestor, Navigator, Atlas, or other Suite identifiers.

Connections should be expressed through Relationships and authoritative references, not through identifier nesting.

CHR identifier identifies the Chronicle Entry.
External identifier identifies the external authoritative object.

Validation Expectations

Chronicle Validation confirms that a Chronicle Entry identifier:

Uses the approved namespace · Uses a valid year · Uses the approved sequence format · Is unique · Has never been reused · Matches the record's assigned identity

First Production Identifier

Chronicle formally assigned its first permanent production identifier on August 22, 2026:

CHR-2026-0001

The identifier was assigned only during the production procedure after Preservation Eligibility, Event Type, Profile applicability, and uniqueness had been confirmed. Its earlier use during the August 20 operational dry run did not assign, reserve, or consume the identifier.

Assignment Year: 2026
Annual Sequence: 0001
Event Date: 2026-07-05
Entry Version: 1

This production precedent confirms that identifier assignment year and Event Date remain independent temporal concepts.

Identifier Principle

Chronicle identifiers should carry enough structure to identify and manage the Entry, but not enough semantics to become fragile when Chronicle evolves.

Identity should be permanent. Meaning should remain in the record.
