Chronicle · Records

Satoshium Chronicle Records

Record is an umbrella term for structured information maintained within Chronicle. The canonical historical-preservation object is the Chronicle Entry. Supporting Source, Evidence, and Correction records may be created where their additional structure provides real institutional value, while Verification, Validation, Provenance, Relationships, Versions, and publication state remain governed aspects of Chronicle's handling of the Entry.

Not every referenced object becomes a Chronicle-owned record. Chronicle may maintain its own supporting records while referencing authoritative objects owned by Certifier, Registry, Atlas, Anchor, Beacon, Attestor, Navigator, and other Suite systems.

Canonical Entry

The Chronicle Entry is the canonical record object through which Chronicle preserves a qualifying historical Occurrence. Supporting records exist only where they perform a distinct operational function and should never become a competing historical-preservation object.

Traceability

Chronicle records should preserve traceable connections among Entries, Sources, Evidence, Provenance, Verification, Validation, Corrections, Versions, publication lineage, and authoritative Suite references so historical context remains reconstructable.

Transparency

Chronicle records should remain reviewable and understandable, including Provenance, Version lineage, Correction history, Relationships to authoritative records, Verification State, Validation result where material, and Publication State.

Authority Boundaries

Chronicle records are authoritative only within Chronicle’s own institutional scope. Referenced Certification Packages, SREGs, Integrity References, Trust Statements, Discovery Signals, Workflow Definitions, Atlas records, and other Suite objects remain authoritative within their originating systems.

Relationships

Chronicle records may connect with one another and with authoritative external Suite objects through stable references. Relationships preserve context without transferring ownership or authority between institutions.

Continuity

Chronicle records support historical continuity by preserving how Entries, Evidence, Relationships, Provenance, Verification, Validation, Corrections, Versions, and publication states evolved over time.

Suite Alignment

Chronicle Records follow Satoshium Suite standards for stable objects, canonical terminology, structured schemas, durable identifiers, Version preservation, explicit Validation, authority-aware references, and documented repeatable production procedures.

Suite Interoperability requires reference-based design: Chronicle references authoritative objects maintained by other Suite institutions rather than duplicating, replacing, or reinterpreting them.

One canonical Chronicle object · Supporting Chronicle records · Referenced external authoritative objects

Record Categories

Chronicle uses one canonical historical-preservation object together with supporting record classes that perform distinct functions. These supporting classes should not be confused with separate canonical Chronicle objects.

Chronicle Entry · Supporting Source Records where useful · Evidence Records where useful · Correction Records where required

Chronicle-Owned vs. Referenced Records

Chronicle should distinguish records it creates and governs from records it only references. It should also distinguish independently maintained supporting records from structures or process results that belong to the Chronicle Entry lifecycle.

Canonical Chronicle Object → Chronicle Entry
Chronicle Supporting Records → Source Record, Evidence Record, Correction Record where operationally justified
Chronicle Entry Structures / Process Results → Provenance, Relationships, Verification, Validation, Version lineage, Publication State
Referenced Authority → Certification Package, SREG, Integrity Reference, Discovery Signal, Trust Statement, Workflow Definition, Atlas record, or other authoritative external object

A reference to an external record does not make that record part of Chronicle’s authority or lifecycle. Reference does not transfer authority.

Record Lifecycle

The Chronicle Entry follows the documented Entry Lifecycle and Production Procedure while preserving prior substantive states where required. Supporting records should use only the lifecycle or Version structure actually required by their own operational function.

Occurrence Identified → Preservation Eligibility → Entry Drafted → References / Sources / Evidence / Provenance / Relationships Assembled → Verification → Validation → Publication Gate → Publication → Maintenance → Correction / Versioning if Necessary → Preservation

Validation Is Not a New Canonical Record

Chronicle's production Validation architecture defines the Validation Record as the information needed to reconstruct a Validation decision, but does not establish a new canonical Validation object or identifier namespace.

The initial implementation preserves full Validation detail through a lightweight institutional Validation artifact associated with the exact Entry Version. Minimal publication-facing Validation information may be referenced where useful.

Record the Validation. Do not inflate the object model.

No Redundant Canonical Layer

Chronicle should not create a second canonical “Record” object above or beside the Chronicle Entry. “Record” is an architectural umbrella term, not a competing historical object.

Production historical preservation should remain centered on the Chronicle Entry. Supporting records exist only where they provide a distinct operational function. Verification, Validation, Relationships, Provenance, Versions, and Publication State should not be promoted into separate canonical objects merely for symmetry.

Record Philosophy

Chronicle favors durable, Version-aware preservation over silent deletion whenever practical. Chronicle-owned records provide value not only because they capture information, but because their Provenance, Relationships, Verification, Validation, Correction history, publication lineage, and Versions reveal how the historical record was maintained over time.

The goal is not to accumulate records for their own sake. The goal is to support coherent, reviewable Chronicle Entries and durable historical continuity.

Chronicle Entries preserve occurrences. Supporting records preserve context, traceability, and lineage.
