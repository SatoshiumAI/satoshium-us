Satoshium Chronicle Status

Chronicle Status describes the institutional state of the Chronicle system itself. It should not be confused with the Lifecycle State, Entry Status, Verification State, Publication State, or other state values assigned to an individual Chronicle Entry.

Chronicle is operational as a production historical-preservation system. Phase VII production schemas are complete, Phase VIII Validation and Entry Production Procedure architecture has been exercised in production, and CHR-2026-0001 is now Chronicle's first canonical published production Entry.

Two Status Layers

Chronicle System Status → Describes Chronicle as an institution / system.
Individual Entry State → Describes the condition of one Chronicle Entry.

These layers should remain separate so the status of the Chronicle system cannot be mistaken for the state of an individual historical record.

Individual Chronicle Entry State

The state of an individual Chronicle Entry is represented through specific, controlled state systems. These values should not be used as Chronicle-wide institutional status labels.

Lifecycle State

Describes where an Entry is in its broader institutional journey.

Draft · Active · Superseded · Withdrawn · Preserved

No Generic Entry Status

Chronicle does not currently treat a generic Entry Status as a canonical production state system. Lifecycle State, Verification State, and Publication State answer distinct institutional questions and should remain explicit.

Avoid generic status when a defined state system already expresses the meaning.

Verification State

Describes the current result of Chronicle's Verification Procedure.

Not Reviewed · In Review · Verified · Verified with Limitations · Unresolved

Publication State

Describes the Entry's position within the controlled publication process.

Not Published · Pending Publication · Published · Withdrawn from Publication

State Systems Must Not Collapse

An Entry can legitimately hold different values across these state systems.

Lifecycle State: Active
Verification State: Verified with Limitations
Publication State: Published

These values describe different institutional questions and should remain distinct. Chronicle should not add a generic Entry Status merely to restate them.

System Status Is Not a Controlled Entry Value

Chronicle's institutional status—such as pre-operational, operational, or retired— is system-level information.

It should not be stored in an Entry's Lifecycle State, Verification State, or Publication State merely because similar words may appear in ordinary language.

Status Philosophy

Status should communicate institutional reality without compressing different state systems into one label.

System status describes Chronicle.
Entry state systems describe Chronicle Entries.
Validation result describes conformance of a specific Entry Version.

The goal is transparent progress, not premature claims of production readiness.
