Chronicle · Certification Event-Type Profile

Satoshium Chronicle Certification Events

The Certification Event-Type Profile defines the certification-specific requirements applied to Chronicle Entries that preserve qualifying certification-related Occurrences.

Certifier remains authoritative for certification determinations, Certification Packages, lifecycle actions, and certification status. Chronicle owns the historical-preservation record representing the qualifying certification Occurrence and preserves that history by referencing the authoritative Certifier record rather than duplicating it.

Purpose

The Certification Event-Type Profile specializes the Chronicle Base Schema for certification-related Occurrences. It adds only the requirements necessary to preserve certification history while maintaining Suite authority boundaries.

Core Distinction

Certifier owns the authoritative certification action and Certification Package. Registry owns any related SREG Registry Entry. Chronicle owns the Chronicle Entry that preserves the qualifying historical Occurrence and its historical context.

Base Schema Relationship

Certification-related Chronicle Entries remain canonical Chronicle Entries. The Certification Event-Type Profile specializes the Base Schema; it does not create a separate canonical Certification Event object.

Chronicle Base Schema + Certification Event-Type Profile = Certification-related Chronicle Entry

Authority Boundary

The Profile may require references to authoritative Certifier records, but it does not reproduce certification findings, evidence packages, status mechanics, or other Certification Package contents owned by Certifier.

Historical Meaning

A Chronicle Entry classified under this Profile preserves what happened, when it happened, which Certifier record establishes the Occurrence, and the historical context needed to understand the Occurrence over time.

Reference-Based Interoperability

Chronicle references Certification Packages, related Registry Entries, integrity references, attestations, public records, or other Suite objects without redefining their schemas or transferring their institutional authority.

Certification Event Types

The Certification Event-Type Profile applies to the approved certification-related Event Types when the represented Occurrence satisfies Chronicle Preservation Eligibility and can be tied to an authoritative Certifier record.

Certification Created → Certification Renewed → Certification Suspended → Certification Revoked → Certification Expired

Certification Created

A Chronicle Entry classified as Certification Created preserves the historical Occurrence in which Certifier created a new authoritative Certification Package. Chronicle references that Package; it does not recreate the certification determination.

Certification Renewed

A Chronicle Entry classified as Certification Renewed preserves the historical Occurrence in which Certifier authoritatively renewed a certification under the applicable certification rules and lifecycle model.

Certification Suspended

A Chronicle Entry classified as Certification Suspended preserves the historical Occurrence in which Certifier authoritatively placed a certification into a suspended state.

Certification Revoked

A Chronicle Entry classified as Certification Revoked preserves the historical Occurrence in which Certifier authoritatively revoked a certification.

Certification Expired

A Chronicle Entry classified as Certification Expired preserves the historical Occurrence in which a certification reached an expired state under the applicable Certifier rules and lifecycle model.

Future Event Types

Additional certification-related Event Types should be added only when they correspond to authoritative Certifier actions or states and are approved through Chronicle Event Type and Controlled Values governance.

What the Profile Requires

The Certification Event-Type Profile uses the Chronicle Base Schema and adds or strengthens only certification-specific requirements.

Event-Type Profile Reference · Approved Certification Event Type · Event Date / Time · Certifier as Originating System · Authoritative Certification Identifier · Historical Context · Certification-Specific Provenance

A related Registry identifier is required when a corresponding SREG Registry Entry exists and is materially relevant to the Chronicle Entry.

Inherited from the Chronicle Base Schema

Certification-related Chronicle Entries inherit the universal Base Schema fields and structures governing Chronicle identity, Versions, historical representation, Provenance, Verification, Lifecycle, Publication, and Entry creation.

entry_id · schema_id · schema_version · entry_version · title · summary · event_type · event_date · historical_context · provenance · verification_state · lifecycle_state · publication_state · entry_created_at

What the Profile Does Not Duplicate

The Certification Event-Type Profile does not reproduce the internal contents of the Certification Package.

Certification findings · Certification evidence body · Certification Package schema · Certification determination logic · Certifier lifecycle mechanics

Those remain within Certifier. Chronicle preserves durable references and the historical meaning of the qualifying Occurrence.

Relationship to Registry

Registry creates and maintains independent SREG Registry Entries. A certification-related Chronicle Entry may reference the related SREG when one exists, but Registry remains authoritative for the catalog record and Registry lifecycle state.

Certifier owns the certification record.
Registry owns the catalog record.
Chronicle owns the historical-preservation record representing the qualifying Occurrence.

Verification

Chronicle Verification reviews Chronicle's historical representation, including the correctness of identifiers, authoritative references, Event Date, Registry references where applicable, Relationships, Provenance, and material limitations.

Verification does not re-adjudicate the certification determination made by Certifier.

Corrections and Versioning

If Chronicle later discovers that its own certification-related Entry is materially wrong, Chronicle corrects and Versions its own record according to Chronicle Correction and Versioning rules.

If Certifier later performs a distinct certification action, that later action may constitute a new qualifying Occurrence and therefore a new Chronicle Entry rather than a rewrite of the earlier historical record.

Profile Philosophy

The Certification Event-Type Profile gives Chronicle the minimum additional structure necessary to preserve certification history without creating a competing certification system or duplicating Certifier-owned records.

Certifier establishes certification authority. Chronicle preserves the historical record of what occurred.
