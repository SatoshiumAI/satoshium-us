Discovery Signals Register

The Discovery Signals Register is Beacon's human-facing index of published canonical Discovery Signals. It provides a stable place to locate Beacon production objects, understand their current institutional state, and follow each register entry to the authoritative Beacon record.

The Register catalogs Beacon objects. It does not create them, replace them, or become a second authority over them.

Purpose

The Register answers:

What Discovery Signals has Beacon published?
What is each signal's BEAC identifier?
What type of discovery does it represent?
What is its current lifecycle state and version?
Where is the individual canonical record?

Institutional Boundary

The Register is a public index over Beacon-owned canonical objects.

Discovery Signal → canonical Beacon object
Register entry → index representation of that object

Register entry ≠ second canonical object

Register Scope

The public Discovery Signals Register is intended to expose Beacon Discovery Signals whose Publication State is Published.

Published Beacon Discovery Signals
↓
/beacon/records/
↓
Human-facing discovery index

Draft, internal, restricted, or otherwise Unpublished signals should not appear in the public Register by default.

Canonical Object

Discovery Signal

The Discovery Signal is the institution-owned Beacon production object.

Index Representation

Register Entry

A Register entry is the human-facing index representation used to locate and summarize a published Discovery Signal.

Register entry points to the Discovery Signal.
It does not replace the Discovery Signal.

Canonical Record Path

Published Discovery Signals are expected to resolve through stable record paths using their BEAC identifiers.

/beacon/records/BEAC-2026-0001/

The next Phase II architecture defines the individual Discovery Signal page represented at that path.

Register Summary

The Register may provide concise discovery context to help users understand why a signal is relevant.

Summary → navigation and discovery aid
Individual record → full Beacon representation

No Canonical Duplication

Register summaries should not become independent copies of the canonical Discovery Signal.

Index enough to discover.
Link to the canonical record for authority and detail.

Current and Historical Signals

The Register should distinguish current published signals from published signals whose lifecycle has later changed.

Active / Published → current institutional discovery

Superseded / Published → historical, replaced for current use

Resolved / Published → historical, governed conclusion reached

Withdrawn / Published → historical publication with withdrawal state preserved where governance permits

Active Signals

Active Published signals should be readily discoverable as current Beacon objects.

Superseded Signals

Superseded Published signals should remain traceable and identify the current replacement when one exists.

Resolved Signals

Resolved Published signals may remain discoverable as part of Beacon's institutional history.

Withdrawn Signals

Previously published Withdrawn signals should preserve the historical fact of publication and governed withdrawal to the extent permitted.

Version Visibility

The Register should identify the current version of each listed Discovery Signal without turning every historical version into a separate canonical Register object.

Source Identity

Register-level source information should preserve attribution without implying that Beacon owns the source object.

Authority Boundary

The Register indexes Beacon Discovery Signals, even when those signals reference other Suite institutions.

Reference does not transfer authority.

Discovery and Filtering

As production volume grows, the Register may support human-facing filtering or organization by governed fields such as:

  • Signal Type
  • Lifecycle State
  • Source Institution
  • Publication date
  • Current vs. historical status
Filtering is a presentation capability. It does not alter the canonical objects or their institutional state.

Register Ordering

Initial ordering may be simple and deterministic, such as canonical identifier or publication chronology.

Exact production ordering remains unfrozen until actual records exist.

Search

Future search may help locate published signals by subject, identifier, type, or source.

Search improves discovery.
It does not change publication eligibility or authority.

Register Inclusion Rule

Canonical Discovery Signal exists
+ Publication State = Published
+ Public representation remains permitted
= Eligible for public Register inclusion

Lifecycle state affects how the signal is represented, not necessarily whether its historical publication remains discoverable.

Unpublished Signals

Unpublished Discovery Signals should not appear in the public Register by default.

Active / Unpublished
≠ public Register entry

Restricted Signals

A valid signal may remain outside the public Register when publication or continuing public representation is restricted by governance.

No Register-Based Authority

Inclusion in the Register establishes public discoverability within Beacon.

It does not independently establish:

  • Truth of an underlying source assertion
  • Certification
  • Registration standing
  • Historical significance
  • Integrity verification
  • Trust
Register inclusion means: Beacon has published this Discovery Signal under its own governed architecture.

Register Integrity

Register entries should remain consistent with the canonical Discovery Signals they index.

Identifier matches
+ Signal Type matches
+ Lifecycle state matches
+ Current version matches
+ Publication state matches
+ Record link resolves correctly
= Register-level conformance

Correction

If a Register summary is incorrect while the underlying canonical record is correct, the index representation should be corrected without changing the Discovery Signal unnecessarily.

Canonical Change

If the Discovery Signal itself changes materially, Versioning & Supersession governs the canonical change and the Register should reflect the resulting current state.

Production Register

No production Discovery Signals have been published yet. Beacon remains in Continuing Development. The first production Discovery Signal will be created only after Phase II architecture and the production methodology are ready for institutional use.
This empty state is intentional. The Register architecture now exists before production evidence exists.

Relationship to Publication

Publication determines whether a Discovery Signal is eligible to appear in the public Register.

Relationship to Versioning

The Register reflects the current version while preserving access to governed historical context through the individual record.

Relationship to Authority

The Register catalogs Beacon-owned objects and preserves the ownership of all referenced endpoints.

Relationship to Validation

Register representation should remain consistent with the validated canonical Discovery Signal it summarizes.

What Is Now Established

  • The Discovery Signals Register is Beacon's human-facing index of published canonical Discovery Signals
  • The Register catalogs Discovery Signals; it does not create them
  • A Register entry is an index representation, not a second canonical object
  • Public Register inclusion normally requires Publication State = Published
  • Unpublished signals remain outside the public Register by default
  • Each Register entry preserves the canonical BEAC identifier
  • Register entries provide concise discovery context and point to individual canonical records
  • The Register should expose current lifecycle state and current version
  • Published Superseded, Resolved, and Withdrawn signals may remain historically discoverable where governance permits
  • Signal Type and Source Object Type remain distinct
  • Source ownership and authority remain preserved
  • Register inclusion does not independently establish truth, certification, registration, integrity, or trust
  • Register summaries must remain consistent with their canonical Discovery Signals
  • The initial production Register is intentionally empty

What Remains Unfrozen

  • Exact production Register field labels
  • Default ordering
  • Filtering controls
  • Search behavior
  • Pagination if production scale requires it
  • Historical-state display details
  • Withdrawn-record visibility mechanics
  • Register correction mechanics
  • Machine-readable register/index representation
  • Whether additional summary fields are useful after first production use
These should be informed by the Individual Discovery Signal architecture and actual production records rather than frozen before use.

Governing Rules

Index only what publication governance permits.
Preserve the canonical BEAC identifier.
Summarize without duplicating canonical authority.
Preserve lifecycle and version context.
Preserve source attribution.
Point users to the individual Beacon record.
Preserve historical discoverability where governance permits.
Never treat Register inclusion as authority beyond Beacon's own role.

The Register makes Beacon's published objects findable without becoming another object itself.
