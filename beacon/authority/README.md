# Satoshium Beacon — Authority & Reference Model

## Overview

The **Authority & Reference Model** defines the institutional ownership boundaries governing Satoshium Beacon.

It formalizes one of the most important principles established during Beacon Phase I:

> **Reference does not transfer authority.**

Beacon is the Satoshium Suite institution responsible for:

```text
Discovery & Signals
```

Its canonical production object is:

```text
Discovery Signal
```

with canonical identifier:

```text
BEAC-YYYY-NNNN
```

Beacon may discover and reference objects owned by other Suite institutions and information originating from external sources.

Those references do not transfer ownership, authority, institutional standing, or responsibility to Beacon.

---

# Purpose

The Authority & Reference Model answers:

```text
What does Beacon own?

What may Beacon reference?

Who continues to own the referenced object?

What authority remains with the originating institution?

What authority, if any, does a reference carry into Beacon?

What must Beacon never claim merely because it discovered something?
```

The governing answer is:

```text
Discovery creates connection.

Reference preserves attribution.

Authority remains with its institutional owner.
```

---

# Core Rule

A Beacon Discovery Signal may point to an authoritative object without:

```text
becoming that object
replacing that object
duplicating that object's authority
inheriting the source institution's authority
```

Conceptually:

```text
Source Institution
        ↓ owns
Canonical Source Object
        ↓ referenced by
Beacon Discovery Signal
```

The reference connects the objects.

It does not collapse them.

---

# Beacon Ownership

Beacon owns the objects and determinations that belong to its own institutional responsibility.

Beacon owns:

```text
Discovery Signals

BEAC-YYYY-NNNN identifiers

Discovery Metadata attached to Beacon signals

Beacon lifecycle state for Beacon signals

Beacon publication state for Beacon signals

Beacon version and supersession information for Beacon signals

Beacon provenance describing Beacon's observation

Beacon Validation determinations about Beacon signals

Beacon-governed relationships represented by Beacon signals
```

Beacon may authoritatively describe:

```text
its own canonical object
its own discovery classification
its own institutional actions
its own lifecycle
its own publication state
its own provenance
its own validation result
```

---

# What Beacon Does Not Own

Beacon does not acquire ownership of:

```text
Atlas Authoritative Intelligence

Certifier Certification Packages

Registry SREG records

Chronicle Entries

Anchor Integrity References

Attestor Trust Statements

Navigator Workflow Definitions

Navigator orchestration authority

external records

external publications

external datasets

external source assertions
```

Those objects and determinations remain with their originating institutions or sources.

---

# Reference Ownership

An important distinction is:

> **Beacon owns the reference relationship as represented within its own Discovery Signal. Beacon does not own the referenced object.**

For example:

```text
BEAC-2026-0001
```

may contain a reference to:

```text
ANCH-2026-0001
```

Beacon owns:

```text
the Discovery Signal
the fact that the Discovery Signal contains the reference
the Beacon-defined discovery context surrounding that reference
```

Anchor owns:

```text
ANCH-2026-0001
the Integrity Reference
the institutional meaning and authority attached to that object
```

# Three-Layer Reference Model

Beacon references can be understood through three distinct layers.

## Layer 1 — Referenced Object

The source or canonical object retains:

```text
native identity
native object type
institutional ownership
institutional authority
source-native status
```

---

## Layer 2 — Beacon Reference

Beacon preserves enough information to identify and understand the referenced object.

Potential reference information includes:

```text
institution
identifier
object type
source location
relationship
observed source status
attribution
```

The reference belongs to Beacon's representation.

The referenced object does not.

---

## Layer 3 — Beacon Discovery Signal

Beacon owns the Discovery Signal explaining why the referenced object is discoverably relevant.

Conceptually:

```text
Referenced Object
        ↓
Beacon Reference
        ↓
Discovery Signal
```

Each layer retains a distinct purpose.

---

# Identity Preservation

Referenced canonical objects must retain their native identifiers.

Example:

```text
BEAC-2026-0001
→ Beacon Discovery Signal

ANCH-2026-0001
→ Anchor Integrity Reference
```

Beacon must not rename:

```text
ANCH-2026-0001
```

as though it were a Beacon-owned object.

The reference should preserve the source object's actual identity.

---

# Object-Type Preservation

Source Object Type and Beacon Signal Type are related but distinct.

Example:

```text
Source Object Type
→ Integrity Reference

Beacon Signal Type
→ Integrity
```

Another example:

```text
Source Object Type
→ Trust Statement

Beacon Signal Type
→ Trust
```

Beacon Signal Type describes the discovery.

Source Object Type describes the referenced object.

One must not silently replace the other.

---

# Authority Attribution

When Beacon exposes a source-owned determination, the determination should remain attributable to its source.

Correct concept:

```text
Registry reports SREG-2026-0001 as [Registry-owned status].
```

Incorrect concept:

```text
Beacon independently assigns Registry standing to SREG-2026-0001.
```

Beacon may report what the source institution says.

Beacon must distinguish that from what Beacon itself determines.

---

# Beacon-Owned Determinations

Beacon may make determinations within its own institutional domain.

These include:

```text
whether a Beacon Discovery Signal exists
which BEAC identifier it possesses
its primary Signal Type
its Discovery Metadata
its Beacon lifecycle state
its Beacon publication state
its provenance record
whether it conforms to Beacon Validation
its Beacon version
its Beacon supersession relationship
its Beacon-governed relationships
```

These are Beacon determinations because they concern Beacon's own canonical object.

---

# Source-Owned Determinations

Beacon must attribute determinations owned elsewhere.

Examples include:

```text
Atlas intelligence authority
Certifier certification decisions
Registry registration standing
Chronicle preservation decisions
Anchor integrity determinations
Attestor trust determinations
Navigator workflow definitions
external source assertions
external source-native status
```

Beacon may observe these determinations.

Observation does not transfer their ownership.

---

# Reference Does Not Equal Endorsement

A Beacon reference means:

```text
the referenced source or object is relevant to the discovery represented by the signal
```

A reference does not automatically mean Beacon:

```text
endorses the source
agrees with every assertion
certifies the source
trusts the source
guarantees source correctness
adopts the source's institutional authority
```

Reference is a governed connection.

It is not blanket endorsement.

---

# Reference Does Not Equal Truth

Beacon can accurately record:

```text
This source made this assertion at the time Beacon observed it.
```

even if the source assertion later proves incorrect.

Therefore Beacon's attributable claim may be:

```text
This is what Beacon observed from this source at this time.
```

It is not automatically:

```text
The underlying assertion is universally true.
```

This distinction aligns the Authority Model with Discovery Provenance.

---

# Reference Does Not Equal Validation

Beacon Validation determines whether:

```text
the Beacon Discovery Signal conforms to Beacon production rules
```

It does not automatically determine whether:

```text
every assertion made by every referenced source is true
```

Therefore:

```text
Valid Beacon Signal
≠
Validated Truth of Every Referenced Claim
```

---

# Reference Does Not Equal Certification

A Beacon Certification Signal may reference:

```text
SC-CERT-2026-0001
```

The certification authority remains with Certifier.

Beacon does not independently certify the subject.

---

# Reference Does Not Equal Registration

A Beacon Registry Signal may reference:

```text
SREG-2026-0001
```

Registration authority remains with Registry.

Beacon does not create or modify Registry standing.

---

# Reference Does Not Equal Historical Authority

A Historical Signal may reference:

```text
CHR-2026-0001
```

Chronicle retains ownership of the Chronicle Entry and its historical preservation role.

Beacon discovery does not itself establish Preservation Eligibility.

---

# Reference Does Not Equal Integrity Authority

An Integrity Signal may reference:

```text
ANCH-2026-0001
```

Anchor retains ownership of the Integrity Reference and its integrity function.

Beacon does not perform Anchor's role merely by exposing the reference.

---

# Reference Does Not Equal Trust

A Trust Signal may reference an Attestor Trust Statement.

Attestor retains trust authority.

Therefore:

```text
Trust Signal
≠
Trust Statement
```

---

# Reference Integrity Requirements

A production reference should preserve enough information to identify what is being referenced without reconstructing the source object inside Beacon.

When applicable, a reference should preserve:

```text
referenced institution or source
native identifier
native object type
source location
relationship to the Discovery Signal
observation provenance
source-owned status with attribution
```

This creates traceability without duplication.

---

# No Canonical Duplication

Beacon should not copy another institution's canonical object into Beacon and then treat the copy as independently authoritative.

The preferred model is:

```text
Reference the canonical object.

Preserve enough context for discovery.

Preserve provenance.

Return to the source institution for source authority.
```

Canonical duplication creates ambiguity about:

```text
ownership
version
status
authority
source of truth
```

The Authority Model avoids that ambiguity.

---

# No Authority Laundering

Beacon discovery visibility must not create an appearance of greater institutional authority than the source actually possesses.

This principle can be stated as:

> **Discovery visibility must never be mistaken for institutional elevation.**

Examples of authority laundering would include:

```text
treating an external assertion as Suite-authoritative merely because Beacon indexed it

treating a Beacon Trust Signal as an Attestor Trust Statement

treating a Beacon Certification Signal as a Certifier Certification Package

treating a referenced source status as a Beacon-owned determination
```

The Authority Model prohibits these collapses.

---

# External Source Boundary

Beacon may preserve external information as:

```text
discovery evidence
source material
supporting context
relationship evidence
```

while clearly distinguishing it from Suite-owned canonical authority.

Conceptually:

```text
External Source
        ↓
observed and attributed
        ↓
Beacon Discovery Signal
```

The External Source remains external.

If another Suite institution later performs an institutional action involving the same subject, that action creates its own institution-owned object.

For example:

```text
External Source
↓
Beacon Discovery Signal

later, separately:

Certifier
→ Certification Package

Registry
→ SREG

Chronicle
→ Chronicle Entry

Anchor
→ Integrity Reference

Attestor
→ Trust Statement
```

Those are separate institutional acts.

---

# Source Changes

A referenced source may later:

```text
change content
change status
move location
be superseded
be withdrawn
become unavailable
```

Beacon may record a later observation.

Beacon may update or supersede its own Discovery Signal according to Beacon rules.

Beacon may not rewrite the source institution's authority.

---

# Broken or Unavailable References

Loss of source availability does not automatically erase:

```text
the Discovery Signal
the original provenance
the historical reference
```

Beacon should preserve, where possible:

```text
the historical reference
the source identity
the original observation
the later availability condition
```

Beacon lifecycle and Versioning rules determine what happens to the Discovery Signal itself.

# Relationship to Discovery Provenance

Authority and Provenance answer different questions.

```text
Authority
→ Whose object or determination is this?

Provenance
→ How did Beacon encounter and preserve it?
```

Together they allow Beacon to say:

```text
This is what Beacon observed.

This is where Beacon observed it.

This is who owns the referenced object.

This is what Beacon owns.

These authorities remain separate.
```

---

# Relationship to Validation

Validation must enforce the Authority & Reference Model where applicable.

A Discovery Signal should fail or require review if it:

```text
misidentifies the source institution
replaces a source-native identifier
claims authority Beacon does not possess
collapses Signal Type and Source Object Type
presents source-owned status as Beacon-owned
creates unsupported canonical duplication
```

Therefore:

```text
Authority Model
→ defines ownership boundaries

Validation
→ checks conformance to those boundaries
```

---

# Relationship to Schemas

Beacon schemas should represent references without recreating source-owned canonical objects.

Schema structures may preserve:

```text

provenance
relationships
attribution
```

The schema should contain enough information for discovery and review.

It should not silently become a duplicate source registry.

# Relationship to Versioning

Beacon may version:

```text
its own Discovery Signal
its own reference representation
its own understanding of a relationship
```

Beacon does not version another institution's canonical object.

If the source object changes version, Beacon may preserve that source-native version information as attributed source context.

---

# Relationship to Publication

Publishing a Discovery Signal does not elevate the authority of its references.

Public visibility means:

```text
Beacon published its Discovery Signal.
```

It does not mean:

```text
Beacon adopted all referenced information as its own authority.
```

Publication must preserve attribution and authority boundaries.

# Governing Authority Principles

Beacon follows these principles:

```text
Own the Discovery Signal.

Preserve the source object.

Preserve native identity.

Preserve institutional attribution.

Preserve provenance.

Distinguish Signal Type from Source Object Type.

Distinguish Beacon determinations from source determinations.

Reference rather than duplicate.

Do not convert visibility into authority.

Do not convert discovery into endorsement.

Do not convert conformance into truth.
```

The Authority & Reference Model reflection is:

> **A reference can carry meaning across institutions without carrying ownership with it.**

The Suite-wide governing principle remains:

> **Reference does not transfer authority.**
