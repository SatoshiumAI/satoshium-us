Registry Entry Model

The Registry Entry Model defines the canonical object preserved by the Satoshium Registry: the Satoshium Registry Entry, or SREG.

What Is an SREG?

An SREG is a Satoshium Registry Entry. It is the Registry’s primary operational artifact: a cataloged, version-aware, publicly referenceable entry that preserves the existence, status, relationships, and source references of an authoritative record.

Why Registry Creates SREG

Registry creates SREG entries so authoritative records produced elsewhere in the Suite can be discovered, referenced, related, and preserved over time without transferring authority away from the system that produced them.

The Core Relationship

The architectural relationship between Certifier and Registry is intentionally direct. Certifier produces the certification. Registry catalogs the resulting public record.

The Certification Package remains the canonical certification. The SCRD is the public Certified Record produced by Certifier. Registry receives the SCRD and creates an independent SREG Registry Entry.

Architectural Principle

Registry preserves records. Registry does not create their authority.

Registry References

Registry references Certification Packages, SCRDs, source systems, and public locations. It does not duplicate the certification itself or modify the package from which the record originates.

Registry Does Not Certify

Certification remains the responsibility of Certifier. Registry does not evaluate evidence, assign scores, issue certificates, or alter certification outcomes. Registry catalogs.

What an SREG Contains

Each Registry Entry contains enough information to identify, locate, classify, relate, and preserve a record over time. The final schema is defined separately, but every SREG is expected to include core registry metadata.

  • Registry Identifier — the unique Registry-level identifier for the entry.
  • Record Type — the classification of the registered record.
  • Source System — the Suite tool or external system that produced the source record.
  • Source Record — the authoritative record being registered.
  • Status — the current Registry status of the entry.
  • Version — the Registry version of the entry.
  • Relationships — preserved links to related records, packages, receipts, attestations, or entries.
  • Public References — public URLs, file paths, or published locations.
  • Registration Date — the date the entry was registered.
  • Last Updated — the date the Registry Entry was last updated.

Relationship to Certification Packages

An SREG may reference a Certification Package, but it does not become the package. The package remains the authoritative certification artifact. The Registry Entry provides a durable catalog layer that makes the package and its public certified record discoverable within the broader Satoshium Suite.

This separation allows Certifier and Registry to preserve distinct responsibilities while still forming a coherent operational chain.

Reference, Do Not Duplicate

Registry avoids unnecessary duplication because duplicated records can drift from their source. By referencing authoritative records instead of copying them, Registry preserves provenance, reduces ambiguity, and supports long-term trust.

Long-Term Discoverability

SREG entries allow records to remain findable after pages move, systems evolve, schemas mature, or future tools are introduced. Registry becomes the catalog layer that helps the Suite remember where records came from and how they relate.

Future Interoperability

Because SREG entries preserve identifiers, relationships, source systems, statuses, and public references, they can support future interoperability across Chronicle, Anchor, Beacon, Attestor, Navigator, and external systems.

Canonical Object Alignment

The Registry Entry Model establishes architectural symmetry across the Suite. Certifier’s canonical object is the Certification Package. Registry’s canonical object is the SREG.

This distinction allows each system to remain clean, intentional, and bounded. Certifier produces authority through certification. Registry preserves the public record of that authority through cataloging.

Institutional Position

An SREG is not a replacement for the record it references. It is the Registry’s institutional acknowledgment that the record exists, has a source, has relationships, has a status, and should remain discoverable.
