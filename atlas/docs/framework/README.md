# Satoshium Atlas — Framework Library

**Path:** `/atlas/docs/framework/`  
**Institution:** Satoshium Atlas  
**Surface:** Atlas Framework Library  
**Status:** Current repository documentation

## Purpose

This directory contains the **Atlas Framework Library**.

The Framework Library preserves Atlas structural doctrine: the canonical framework documents that define interpretation boundaries, protocol rules, topology authority limits, update discipline, and related structural behavior across the Atlas jurisdiction-intelligence system.

The public page for this directory is:

- `index.html`

This README documents the repository role and architectural boundaries of the Framework Library. It does not replace the public presentation in `index.html`.

## Framework Library Role

Framework documents sit beneath Atlas institutional authority and above specific navigation or interpretation surfaces.

They define structural rules before those rules are expressed through public navigation, jurisdiction packages, corridor surfaces, exports, or other Atlas views.

Conceptually:

```text
Atlas Institutional Purpose
        ↓
Framework / Doctrine Documents
        ↓
Interpretation Rules
        ↓
Atlas Operational / Navigation Surfaces
```

Framework documents are not jurisdiction packages.

They are not independent Suite institutions.

They are Atlas-owned structural doctrine.

## Current Framework Documents

The current Framework Library includes three primary doctrine surfaces.

### Federal Overlay Model

Defines how national-scale federal infrastructure overlays interact with jurisdiction and corridor interpretation without becoming the origin authority for Atlas topology.

The model addresses:

- overlay authority limits;
- overlay categories;
- interaction with Atlas topology structures;
- rendering boundaries; and
- compliance rules.

### Signals Update Protocol

Defines how jurisdiction signals evolve while preserving evidence-to-signal derivation integrity and downstream synchronization discipline.

The protocol addresses:

- signal update triggers;
- structural vs. observational change;
- evidence → signal derivation;
- corridor-assignment synchronization;
- export compatibility; and
- update-process discipline.

### Global Adjacency Model

Defines how non-domestic infrastructure continuity interacts with domestic Atlas interpretation without granting external systems authority over Atlas topology placement.

The model addresses:

- cross-border continuity;
- Canadian and Mexican adjacency;
- maritime and Arctic adjacency;
- transoceanic relevance;
- rendering boundaries; and
- compliance rules.

## Structural Doctrine Boundary

The Framework Library defines how Atlas interprets structure.

It does not automatically create:

- new jurisdiction signals;
- new canonical jurisdiction records;
- certification decisions;
- Registry records;
- Chronicle entries;
- Anchor Integrity References;
- Beacon Discovery Signals;
- Attestor Trust Statements; or
- Navigator workflow definitions.

Framework rules may shape how Atlas-owned information is interpreted or rendered, but they do not transfer institutional authority outside Atlas.

## Relationship to Evidence and Signals

Atlas Framework documents may define how evidence and signals are interpreted, updated, synchronized, or constrained.

The governing direction remains:

```text
Evidence
        ↓
Governed Atlas Interpretation
        ↓
Signals
        ↓
Downstream Atlas Structures
```

Framework documents must not introduce unsupported signals merely to satisfy a topology or rendering model.

Signal authority remains tied to the applicable Atlas evidence and jurisdiction record.

## Relationship to Topology

The Framework Library may define rules affecting:

- corridor interpretation;
- adjacency;
- overlay behavior;
- topology continuity;
- rendering;
- assignment synchronization; and
- cross-jurisdiction structural interpretation.

Those rules should preserve the distinction between:

- source evidence;
- jurisdiction signals;
- topology interpretation; and
- presentation.

Topology doctrine should not be mistaken for source authority.

## Relationship to Corridors

Framework documents may constrain how corridor structures are created, updated, synchronized, or rendered.

Corridors remain Atlas-owned descriptive topology structures.

Framework rules do not themselves create corridor membership unless the applicable Atlas process establishes that membership from governed evidence and signals.

## Relationship to Global Adjacency

The Global Adjacency Model allows Atlas to interpret external continuity without transferring Atlas topology authority to an external system.

External infrastructure, jurisdictions, or systems may influence adjacency interpretation.

They do not automatically determine Atlas classifications.

## Relationship to Federal Overlays

Federal overlays may reinforce or contextualize Atlas topology.

They should not override the evidence-derived jurisdiction and corridor structures that remain upstream within Atlas.

Overlay context is therefore distinct from topology origin authority.

## Relationship to Suite Architecture

The Framework Library belongs to Atlas.

It is not a Suite-wide standards layer.

The established Suite boundary remains:

- Suite Standards define expectations.
- Suite Methodology defines implementation.
- Atlas remains authoritative for Atlas institutional records and Atlas-owned structural doctrine.
- Other Suite institutions remain authoritative for their own canonical objects.

Framework documents may be referenced elsewhere in the Suite where relevant.

**REFERENCE DOES NOT TRANSFER AUTHORITY.**

## Trust-Related Interpretation

The public Framework Library page refers to **trust interpretation** as one of the structural concerns governed by framework documents.

That language should remain bounded to Atlas interpretation.

It should not be treated as equivalent to:

- Attestor rule-constrained evaluation;
- an Attestor Trust Statement; or
- universal truth determination.

Atlas trust-related interpretation remains an Atlas structural context unless explicitly handed to another governed institutional process.

## Repository Expectations

Changes to this directory should preserve:

1. Atlas ownership of framework doctrine;
2. separation between framework rules and jurisdiction records;
3. evidence-to-signal derivation integrity;
4. topology authority boundaries;
5. overlay and adjacency limits;
6. corridor synchronization discipline;
7. clear separation between interpretation and source authority;
8. separation between Atlas trust interpretation and Attestor Trust Statements; and
9. consistency across framework documents and their public navigation.

Changes that would redefine Atlas institutional authority, create new Suite-wide rules, alter trust semantics, or change cross-institution boundaries require governed architectural review rather than a documentation-only edit.

## Governing Principle

**Atlas framework documents define interpretation boundaries before those boundaries become operational or navigational surfaces.**
