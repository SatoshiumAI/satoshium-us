Attestor · Advanced Architecture

Controlled Values

Controlled Values establish the normative vocabularies Attestor uses to classify governed objects, states, relationships, provenance, authority context, and evaluation outcomes consistently.

The purpose is semantic discipline rather than scoring. Controlled values constrain institutional meaning so later schemas, validation, conformance, publication, and production can operate against stable vocabulary.

Governing discipline: A controlled value classifies meaning within a defined field or relationship. It does not independently establish truth, authority, evidence sufficiency, or trustworthiness.

Vocabulary Discipline

Controlled Values give repeated Attestor concepts one governed meaning. A value may be used normatively only when its meaning, scope, and permitted use are defined by Attestor architecture; free-form labels must not silently become institutional states or outcomes.

Attestation Types

Attestation Type values classify the nature of the assertion without deciding its truth or evaluation outcome. The initial controlled families are identity, evidence, source-provenance, verification-related, relationship-condition, and correction-supersession. Their formal profile requirements remain subject to the relevant schema and lifecycle architecture.

Lifecycle States

Attestor-owned objects use a bounded lifecycle vocabulary. The initial controlled states are draft, active, superseded, withdrawn, and retired. State transitions and object-specific applicability are governed later by Lifecycle.

Publication States

Canonical existence and public representation remain separate. Publication vocabulary is unpublished and published. Publication does not determine lifecycle state, validity, or evaluation outcome.

Evaluation Outcomes

Attestor evaluation uses conclusion-oriented outcomes rather than confidence scores. The initial controlled outcomes are supported, partially-supported, not-supported, contradicted, and indeterminate. Evaluation will define the evidentiary and rule conditions for each.

Relationship Types

Relationships describe governed connections without transferring ownership or authority. Initial controlled relationships are supports, references, derived-from, evaluates, results-in, supersedes, corrects, and related-to. Formal directionality and cardinality are deferred to Relationships.

Provenance Modes

Provenance must distinguish how Attestor obtained or knows an input. Initial controlled provenance modes are direct, referenced, and derived. Provenance will define exact eligibility and required metadata.

Authority Context

Authority vocabulary must distinguish who owns or governs meaning. Initial controlled authority contexts are Attestor, Suite-source, and external-source. These values classify authority context; they do not rank authority or trustworthiness.

Evaluation Is Not a Confidence Score

Attestor does not adopt the June-era confidence-scale or generic Trust Signal model as a normative controlled vocabulary. Evaluation outcomes express a bounded institutional conclusion about the assertion under review; they are not percentages, reputation scores, generalized confidence ratings, or automatic measures of trust.

Evaluation Outcome ≠ Confidence Percentage
Evaluation Outcome ≠ Reputation Score
Evaluation Outcome ≠ Trust Signal
Evaluation Outcome ≠ Universal Truth

Attestor → Trust Statement

State Is Not Outcome

Lifecycle state, publication state, validation result, and evaluation outcome answer different institutional questions and must remain separate. An Active object is not necessarily Published; a Published object is not necessarily favorable; and a structurally Valid object does not imply that its assertion is Supported.

Lifecycle State → Where the object is in governed existence
Publication State → Whether a public representation is authorized
Validation Result → Whether structural and rule requirements are satisfied
Evaluation Outcome → What Attestor concludes from the governed evaluation

Validation and Conformance Values

This page does not prematurely establish the final result vocabulary for Validation or Conformance. Those stages require their own normative rules before their controlled outcomes can be fixed. Their values will be added to the Attestor vocabulary only when the corresponding architecture defines exactly what each result means.

Validation result vocabulary → Reserved for Validation
Conformance result vocabulary → Reserved for Conformance
Schema constraints → Reserved for Schemas
Transition rules → Reserved for Lifecycle
Relationship directionality → Reserved for Relationships

Extensibility Rule

Controlled vocabularies may be extended only through governed architectural change. New values must have a defined meaning, a defined place in the Attestor object model, and no unresolved collision with existing Suite terminology. Implementations must not create unofficial values and treat them as canonical Attestor vocabulary.

Need identified → Meaning defined → Authority collision checked → Architecture updated → Validation updated → Value becomes canonical

Unregistered label → Not a canonical controlled value

Authority Boundary

Controlled Values govern Attestor's own semantic use. They do not redefine values owned by source institutions. When Attestor references a Certifier status, Registry state, Chronicle event type, Anchor result, Beacon Signal Type, Atlas classification, Navigator workflow state, or external vocabulary, the source meaning remains authoritative.

Attestor vocabulary → Governs Attestor meaning
Source vocabulary → Retains source meaning
Mapping → Must remain explicit where needed

Governing principle: Reference does not transfer authority.
