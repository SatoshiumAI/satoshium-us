Attestor · Schemas

Schemas

This area preserves foundational candidate structures for representing Attestations and related Attestor concepts without prematurely treating June-era field sets, identifiers, statuses, or controlled values as adopted technical standards.

Canonical responsibility: Attestor → Trust Statement
Governing principle: Reference does not transfer authority.

Attestation Schema

Candidate structural profile for a governed, attributable Attestation. Scope, provenance, authority, and traceability are now explicit architectural requirements.

Evidence Attestation

Candidate specialization for bounded assertions concerning Evidence and its relationship to a subject or assertion.

Source Attestation

Candidate specialization for source, provenance, relevance, and source-relationship assertions.

Correction Profile

Candidate structure for governed change to Attestor-owned Attestations. The final correction/lifecycle object model remains unresolved.

Trust Signal — Legacy

The June Trust Signal schema is retained for architectural history, but Trust Signal is not a canonical Attestor object. Useful fields may later inform evaluation context.

Normative Schemas — Deferred

Identifiers, exact required fields, controlled values, lifecycle states, validation rules, machine serialization, and conformance belong to Advanced Architecture.

Foundational Relationship

Eligible Governed Inputs → Attestation → Rule-Constrained Evaluation → Trust Statement

The purpose of this directory at the foundational stage is to preserve useful structural thinking while preventing conceptual drafts from becoming accidental technical canon.
