Attestor · Interoperability

Interoperability

Attestor is designed to participate in the Satoshium Suite by referencing and exchanging governed information while preserving the provenance, scope, meaning, identifiers, status, relationships, and authority of the objects involved.

Interoperability allows information to participate in an Attestor evaluation without collapsing institutional boundaries or converting a referenced object into an Attestor-owned object.

Governing principle: Reference does not transfer authority.

Atlas Interoperability

Attestor may reference authoritative Atlas intelligence when relevant to an evaluation. Atlas retains authority over its intelligence and structural record; Attestor governs only its use within Attestor evaluation.

Governed Relationship

What Must Travel With a Reference

Interoperability is not satisfied merely by transferring a value or identifier. Attestor should preserve enough information to understand what the referenced object is, where it came from, how it relates to the evaluation, and what authority and limitations remain attached to it.

Identifier + Source + Provenance + Type + Status + Scope + Relationship + Authority

These reference-context requirements are established by Attestor's Reference Profile, Authority, Provenance, Relationships, Eligibility, and state architecture. Exact machine serialization remains implementation work.

Reference, Do Not Duplicate Authority

Where a governed Suite object already exists, Attestor should reference that object rather than silently recreate it as an Attestor record. Attestor may preserve the information necessary to evaluate and trace the reference, but the originating object remains authoritative in its source institution.

Source Object → Governed Reference → Eligibility Determination → Attestation / Evaluation Basis → Rule-Constrained Evaluation → Trust Statement

Change Across Institutional Boundaries

Referenced objects may later change status, version, publication state, or other governed properties. Attestor preserves the relevant source state used during Evaluation and distinguishes it from later source changes. A material source-state change may trigger Review, but Review does not predetermine correction, withdrawal, supersession, or creation of a new canonical object.

Attestor does not perform the source institution's lifecycle operation. It responds within its own authority to the consequences of that change.

Source State at Evaluation ≠ Later Source State
Material Source-State Change → Review
Review ≠ Automatic Outcome
