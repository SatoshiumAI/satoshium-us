Attestor · Operational Provenance

Provenance

The Attestor Provenance architecture defines the information and lineage that must remain traceable across Attestations, eligible governed inputs, evaluation, and resulting Trust Statements.

Provenance allows Attestor to show not merely what conclusion it produced, but where the material basis came from, how that basis entered the process, and how the conclusion remains connected to it over time.

Provenance chain: Source / Origin → Governed Input → Attestation → Rule-Constrained Evaluation → Trust Statement

Attestation Provenance

An Attestation must preserve enough provenance to identify where its assertion originated, who or what stands behind it, how it entered Attestor, and which governed references materially support it. Provenance remains distinct from the assertion itself.

Input Provenance

Every material input used in evaluation must remain traceable to its source or derivation path. Attestor must preserve source identity, source identifier where available, provenance mode, relevant state or time, and the relationship between the input and the evaluation.

Evaluation Provenance

Attestor must preserve the governed basis of an evaluation: which Attestation was evaluated, which eligible inputs were considered, which rules or methodology governed the assessment, and enough process context to make the resulting conclusion reviewable.

Trust Statement Provenance

A Trust Statement must remain traceable to the Attestation, eligible governed inputs, evaluation basis, and Attestor process that produced it. Publication or later lifecycle change must not sever that provenance chain.

Direct Provenance

direct provenance applies when Attestor receives or resolves an input directly from the authoritative or originating source context being referenced. Direct provenance describes the path of acquisition; it does not make the content automatically sufficient or correct.

Referenced Provenance

referenced provenance applies when an Attestor object identifies and relies upon an existing governed source through an explicit reference rather than reproducing or taking ownership of that source object.

Derived Provenance

derived provenance applies when an input, assertion, or evaluation element is produced from one or more prior governed inputs. The derivation path must remain traceable enough to identify the material sources and transformation or reasoning context.

Provenance Preservation

Corrections, supersession, withdrawal, retirement, version changes, and publication changes must preserve historical provenance. A current object may change state, but Attestor should remain able to show the governed basis and lineage of prior states where required.

Every material provenance relationship must preserve enough context to identify and interpret its origin and use. Controlled Provenance Modes

The Controlled Values architecture establishes three provenance modes. Their governed use is now represented in canonical Attestor objects and exercised in production, while Schemas and Validation govern applicable serialization and validation requirements.

direct → obtained or resolved directly from the authoritative/originating source context

referenced → connected to an existing governed source through an explicit reference

derived → produced from one or more prior governed inputs through a traceable derivation path

Provenance Across Evaluation

Evaluation must not become a provenance break. The Trust Statement should remain connected backward through the Attestor evaluation to the Attestation and material eligible inputs considered. Where an input is excluded, conflicting, superseded, or otherwise materially affects interpretation, the evaluation record must preserve enough context for that treatment to be reviewable.

Trust Statement → traces to → Evaluation Basis
Evaluation Basis → traces to → Attestation + Material Eligible Inputs
Attestation / Inputs → trace to → Source / Origin

Evaluation transforms institutional meaning; it does not erase lineage.

Source State at Evaluation

Because governed source objects may change after evaluation, Attestor must preserve enough provenance to distinguish the source state evaluated from a later source state. A current source representation must not silently replace the historical basis on which an earlier Trust Statement was produced.

Source State at Evaluation → Preserved or resolvable
Later Source State → Distinguishable
Historical Trust Statement Basis → Remains traceable
Material source change → May trigger review under later Lifecycle / Methodology rules

Provenance and Authority

Provenance identifies lineage; Authority identifies who legitimately stands behind an assertion, source object, process, or conclusion. The two reinforce accountability but are not interchangeable. A well-documented provenance path does not create authority that the source did not possess.

Provenance → Where it came from and how it reached Attestor
Authority → Who legitimately stands behind it and within what bounds

Provenance ≠ Authority
Reference does not transfer authority.

Provenance and Eligibility

Traceable provenance is necessary to evaluate whether many inputs are eligible, but provenance alone does not make an input admissible. Eligibility determines whether a governed input may enter a particular evaluation based on purpose, scope, authority context, source state, relationship, and applicable rules.

Traceable Provenance → Supports eligibility determination
Eligibility → Governs admission to evaluation
Evaluation → Produces Attestor conclusion

Provenance ≠ Eligibility ≠ Evaluation Outcome

Provenance Does Not Establish Truth

A complete provenance chain demonstrates traceability, not correctness. Attestor may know exactly where an assertion came from and still determine that the assertion is partially supported, not supported, contradicted, or indeterminate under the applicable evaluation rules.

Traceable ≠ Correct
Authoritative Source ≠ Automatically Eligible
Eligible Input ≠ Automatically Sufficient
Complete Provenance ≠ Favorable Trust Statement
