Attestor · Advanced Architecture

Lifecycle

Lifecycle defines how Attestor-owned objects move through governed existence: preparation, canonical Creation, review, active use, correction, supersession, withdrawal, and retirement.

Lifecycle preserves continuity without confusing current state with historical state. An Attestation or Trust Statement may cease to be current while remaining permanently identifiable, attributable, and traceable.

Lifecycle principle: State may change. Canonical identity and governed history remain traceable.

Lifecycle Purpose

Lifecycle governs the institutional existence of Attestor-owned objects from preparation through canonical use and eventual historical disposition. It keeps current state distinguishable from prior state without destroying identity, provenance, or lineage.

Draft

draft is the pre-active governed state used while an Attestation or Trust Statement is being prepared, reviewed, or completed. A draft is not yet an active Attestor representation and must not be presented as though it were.

Active

active means the Attestor-owned object is the current governed representation within its scope. Active does not mean published, favorable, permanently correct, or immune from later review.

Superseded

superseded means a newer governed object or version has replaced the prior object as the current representation for the applicable scope. The superseded object remains historically identifiable and traceable.

Withdrawn

withdrawn means Attestor has affirmatively removed the object from current institutional reliance because it should no longer function as an active representation. Withdrawal preserves the historical object and the reason/context for the change where material.

Retired

retired means the object has reached a terminal non-current state through normal institutional disposition rather than necessarily because it was erroneous. Retirement preserves history while signaling that the object is no longer maintained as current.

Correction

Correction is a governed change process, not a lifecycle state. A correction may amend a version, create a successor, or trigger supersession depending on materiality and Versioning rules. The prior state must remain traceable.

Review

Review is a governed lifecycle activity, not a permanent state in the initial controlled vocabulary. Review may confirm continued active status or lead to correction, supersession, withdrawal, retirement, or a new evaluation.

Canonical Lifecycle States

The Controlled Values architecture established five lifecycle states. This page now defines their institutional meaning. Review and correction are governed activities that may cause state transitions; they are not additional lifecycle states in the initial vocabulary.

draft → governed preparation / pre-active state
active → current governed representation within scope
superseded → replaced by a newer governed representation
withdrawn → affirmatively removed from current institutional reliance
retired → terminal non-current disposition

Review → lifecycle activity
Correction → governed change activity

Creation

Canonical Creation is the point at which an Attestor object becomes institutionally recognized and receives its canonical identity. Creation does not require immediate activation or publication. An object may be created in draft state and proceed through governed review before becoming active.

Preparation → No canonical object
Canonical Creation → Identifier assigned
Created Object → draft
Governed Review / Completion → active when requirements are satisfied

Creation ≠ Activation ≠ Publication

Review

Review determines whether an Attestor-owned object remains suitable for its current lifecycle position. Review may be initial, periodic, event-driven, or triggered by material changes to source state, provenance, authority, scope, evidence, evaluation basis, or related objects.

Review → Confirm current state
or → Correct
or → Supersede
or → Withdraw
or → Retire
or → Initiate new evaluation

Review itself does not silently change the object.

Active and Inactive

active is the only initial lifecycle state representing current institutional use. “Inactive” is retained as a descriptive umbrella, not a canonical state value. Superseded, withdrawn, and retired objects are all non-active for different governed reasons and must remain distinguishable.

Active → canonical lifecycle state
Inactive → descriptive category only

Non-active objects:
superseded · withdrawn · retired

Different reasons → Different canonical states

Correction and Materiality

A correction addresses an error, omission, ambiguity, or other material defect in an Attestor-owned object. Minor changes may be handled through versioned correction while preserving the canonical object identity. A change that alters the substantive assertion, evaluation basis, scope, or conclusion may require a successor object and supersession. Exact thresholds belong to Versioning.

Correction Need → Assess Materiality
Non-substantive / bounded correction → Versioned governed change may preserve object identity
Substantive change to object meaning → New canonical object may be required
Successor Object → supersedes → Prior Object

Correction ≠ Deletion

Withdrawal vs. Retirement

Withdrawal and retirement are both non-current states but communicate different institutional meanings. Withdrawal is an affirmative decision that the object should no longer be relied upon as current. Retirement is normal terminal disposition when an object no longer needs to remain current or maintained.

withdrawn → removed from current reliance because continued active use is no longer appropriate
retired → ended through normal lifecycle disposition

Neither state erases the historical object.

Supersession

Supersession preserves continuity when a newer governed object replaces an earlier one as the current representation. The successor must explicitly relate to the prior object, and the prior object remains resolvable as historical state.

New Object → supersedes → Prior Object
New Object → may become active
Prior Object → superseded
Prior Identity / Provenance / History → Preserved

Supersession ≠ Mutation of history

Lifecycle Triggers

Lifecycle review may be triggered when information material to an Attestation or Trust Statement changes. The trigger does not predetermine the resulting state; it requires governed review under applicable rules.

Material Source-State Change
Material New Eligible Input
Authority Change
Provenance Defect or Clarification
Scope Change
Correction Request
Conflicting / Contradictory Information
Evaluation Basis Change
Methodology / Rule Change, when applicable

Trigger → Review, not automatic outcome

Lifecycle and Publication

Lifecycle state and publication state remain independent dimensions. An active object may be unpublished, and a previously published object may later become superseded, withdrawn, or retired while its historical public representation remains governed according to Publication architecture.

Lifecycle State → draft · active · superseded · withdrawn · retired
Publication State → unpublished · published

Active ≠ Published
Published ≠ Active forever
Lifecycle transition ≠ Automatic deletion of publication history

Historical Preservation

Lifecycle changes must preserve enough history to reconstruct the governed sequence of material states. Attestor should be able to distinguish what was current, what changed, why the change occurred where material, and which object or version became current afterward.

Prior State → Governed Change → Current State
Canonical Identifier → Preserved according to object/version rules
Relationships → Preserved
Provenance → Preserved
Material Reason / Trigger → Reviewable
Historical State → Distinguishable from Current State

What Lifecycle Does Not Establish

Lifecycle state describes institutional status over time. It does not independently establish truth, evidence sufficiency, evaluation outcome, publication, validation, conformance, or authority.

Active ≠ True
Active ≠ Supported
Active ≠ Published
Active ≠ Validated
Superseded ≠ False
Withdrawn ≠ Historical Erasure
Retired ≠ Invalid

Advanced Architecture Position

The Lifecycle architecture now defines how Attestor-owned objects become current, remain reviewable, and leave current use without losing historical identity. Versioning can now determine how changes within an object differ from changes that require a new canonical object.

Lifecycle → Established
States → draft · active · superseded · withdrawn · retired
Creation → Canonical identity assignment
Review → Governed lifecycle activity
Correction → Governed change activity, not state
Inactive → Descriptive umbrella, not canonical value
Supersession / withdrawal / retirement → Distinguished
Historical preservation → Required
Publication state → Independent
Detailed version thresholds → Deferred to Versioning
Production proof → Pending
