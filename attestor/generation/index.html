Attestor · Operational Architecture

Attestation Generation

Attestation Generation defines how a bounded trust-relevant matter, attributable assertion, eligible governed inputs, provenance, scope, and authority context are assembled into a canonical Attestation.

Generation does not convert a source object into an Attestation. It creates a new Attestor-governed assertion whose references remain traceable to their originating authorities.

Generation principle: Bounded Matter + Attributable Assertion + Eligible Governed Inputs + Preserved Authority / Provenance → Canonical Attestation

Purpose

Generation establishes the governed path from an evaluation purpose and bounded assertion to a canonical Attestation ready to participate in Rule-Constrained Evaluation.

Canonical Output

The output of Attestation Generation is an Attestor-owned Attestation identified by the ATT-YYYY-NNNN identifier family. Identifier assignment occurs only at canonical creation.

Input Boundary

Potential source material must first satisfy the applicable Eligibility requirements. Availability, authority, technical accessibility, or reference alone does not make an input eligible.

Authority Boundary

Source authority remains with the source institution. Generation preserves attribution and authority context rather than absorbing source authority into Attestor.

Assertion Boundary

The Attestation carries a governed attributable assertion. It is not the source object, not the Evaluation Outcome, and not the eventual Trust Statement.

Evaluation Boundary

Generation does not determine whether the assertion is supported. That determination belongs to Rule-Constrained Evaluation after the Attestation and Evaluation Basis have been established.

Canonical Generation Sequence

The standing generation process preserves the distinction between source material, Eligibility, assertion formation, canonical creation, and later Evaluation.

1. Establish bounded purpose and subject
2. Define assertion and scope
3. Establish Attesting Authority / attribution
4. Identify potential governed inputs
5. Preserve source identity, provenance, relevant state, and authority context
6. Determine Eligibility for the specific evaluation
7. Associate eligible governed references with the assertion
8. Preserve material limitations and uncertainty
9. Create the canonical Attestation
10. Assign ATT identifier at canonical creation
11. Preserve lifecycle, publication, version, provenance, and relationship metadata
12. Pass the Attestation forward to Evaluation Basis / Rule-Constrained Evaluation

What Generation Does Not Do

Attestation Generation is a formation and canonical-creation process. It does not certify the subject, validate universal truth, establish an Evaluation Outcome, create a Trust Statement, authorize publication, or transfer authority from referenced sources.

Source Object ≠ Attestation
Eligibility ≠ Evaluation Outcome
Attestation ≠ Trust Statement
Canonical Creation ≠ Lifecycle Activation ≠ Publication
Reference ≠ Support
Reference does not transfer authority.

First Production Generation Demonstration

The first controlled production operation exercised this process through ATT-2026-0001. The governed matter concerned the canonical identity, attributable Certifier origin, relevant certification state, and traceable Suite relationships of SC-CERT-2026-0001.

Production Attestation Generation → DEMONSTRATED

Production Assertion

The first canonical production Attestation asserted that SC-CERT-2026-0001 is the canonical Satoshium Certifier Certification Package for the Operational certification of the Satoshium Atlas Jurisdiction Record — El Salvador; that it is attributable to Satoshium Certifier; that the canonical Certifier source represents it as Issued · Active; and that it has traceable governed relationships to SREG-2026-0001, CHR-2026-0001, ANCH-2026-0001, and BEAC-2026-0001, while each referenced Suite institution retains authority over its own object and institutional domain.

The assertion was the object of later evaluation. Its canonical creation did not establish that the assertion was supported.

Generation and Source Authority

The first production operation demonstrated that Attestor can create a new canonical Attestation from a governed matter involving existing Suite objects without recreating those source objects or taking over their authority.

SC-CERT-2026-0001 → Certifier authority preserved
SREG-2026-0001 → Registry authority preserved
CHR-2026-0001 → Chronicle authority preserved
ANCH-2026-0001 → Anchor authority preserved
BEAC-2026-0001 → Beacon authority preserved
ATT-2026-0001 → Attestor-governed Attestation

Generation and Later Governance

Canonical creation begins the Attestation's governed history; it does not complete it. Validation, Review, Conformance, lifecycle activation, Publication, correction, supersession, and later review remain separate governed acts where applicable.

Canonical Creation → ATT exists
Validation / Review → Separate determinations
Conformance → Separate determination
Lifecycle Activation → Separate governed act
Publication → Separate governed act

Creation ≠ Activation ≠ Publication

Current Generation Position

Attestation Generation is established as institutional architecture and has been exercised in production. The first operation confirms that a bounded attributable assertion can be canonically created while preserving Eligibility, provenance, relationships, scope, limitations, source authority, and the separation between creation and Evaluation.
