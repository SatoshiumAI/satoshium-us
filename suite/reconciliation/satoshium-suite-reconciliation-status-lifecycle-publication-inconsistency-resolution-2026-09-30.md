## Lifecycle State

Lifecycle state describes the operative condition of the canonical object.

Examples may include institution-specific states such as:

```text
Draft
Active
Superseded
Withdrawn
Resolved
```

where defined by the governing institution.

Lifecycle state does not establish:

```text
truth

publication

Validation

Conformance

certification

support
```

---

## Publication State

Publication state describes whether an object or representation is publicly accessible.

Publication does not create the canonical object.

Publication does not activate the object by itself.

Publication does not establish validity, truth, support, certification, or source authority.

A superseded object may remain published for historical traceability.

A withdrawn object is not automatically unpublished unless the governing publication rules expressly say so.

---

## Validation and Conformance

Validation and Conformance remain separate from lifecycle and publication.

```text
Validation
→ determination against applicable institutional requirements

Conformance
→ determination against an explicit requirement set

Publication
→ accessibility decision

Lifecycle
→ operative-state decision
```

A VALID object may remain unpublished.

A published object may later fail a different or later Validation context.

NOT-TESTED does not become PASS.
