# Satoshium Suite Reconciliation — Legacy Architecture / Layer Audit

**Date:** September 25, 2026  
**Phase:** Phase I — Baseline & Institutional Architecture  
**Decision Class:** RECONCILE  
**Status:** COMPLETE — APPROVED

---

## Purpose

This record audits legacy Satoshium architecture and layer models that predate the mature eight-institution Suite.

The purpose is not to erase or rewrite historically accurate architecture.

It is to determine which legacy descriptions remain useful as historical or capability-oriented models and which should no longer be treated as the current formal Suite architecture.

The governing boundary is:

> **README reconciliation documents the architecture that exists. Suite Reconciliation determines the current formal architecture without rewriting accurate history.**

---

## Current Formal Suite Architecture

The current Satoshium Suite consists of exactly eight formal institutions:

```text
Atlas
Navigator
Certifier
Registry
Chronicle
Anchor
Beacon
Attestor
```

All eight are:

> **Operational**

Aegis remains:

> **External / Pre-Suite**

The mature architecture is institution-based rather than layer-based.

---

## Legacy Architecture Models Identified

Earlier Satoshium architecture used or referenced broad conceptual layers and platform-oriented groupings, including terminology such as:

```text
Trust Layer
Knowledge Layer
Intelligence Layer
Signal Layer
Agent Layer
Simulation Layer
Interface Layer
AI Platform Layer
```

These terms may have been useful during earlier architecture formation.

They do not, by themselves, represent the current formal Suite institutional model.

---

## Reconciled Determination

The legacy layer models are best treated as:

> **historical / capability taxonomies**

rather than:

> **current formal institutional architecture**

Accordingly:

```text
Legacy Layer Model
≠
Formal Suite Institutional Model
```

The two can coexist where their purpose is made clear.

---

## Why the Distinction Matters

Layer terminology tends to describe:

- capabilities;
- functions;
- conceptual groupings;
- platform concerns;
- implementation domains.

The mature Suite defines:

- institutions;
- institutional authority;
- canonical objects;
- lifecycle ownership;
- governed relationships;
- operational responsibility.

These are different architectural dimensions.

A capability layer may span several institutions.

An institution may also participate in more than one capability domain.

Therefore:

> **Capability taxonomy must not be mistaken for institutional authority.**

---

## Trust Layer

The legacy concept of a **Trust Layer** requires particular caution.

In the mature Suite, trust-related responsibilities are distributed across several institutions:

```text
Certifier
→ Operational Certification

Anchor
→ Integrity Preservation

Beacon
→ Discovery & Signals

Attestor
→ Governed Attestation & Rule-Constrained Evaluation
```

No single omnibus Trust Layer owns all trust-related authority.

Therefore:

> **Legacy Trust Layer ≠ current formal trust authority layer**

And:

> **Attestor does not inherit universal trust authority merely because it performs governed trust evaluation.**

---

## Knowledge / Intelligence Layers

Earlier Knowledge or Intelligence layer descriptions may remain historically useful.

The mature institutional architecture now assigns a defined role to Atlas:

> **Authoritative Intelligence**

through the:

> **Jurisdiction Intelligence Package**

This does not mean Atlas owns every historical Knowledge or Intelligence function that may have appeared in earlier platform descriptions.

Therefore:

> **Legacy knowledge/intelligence taxonomy ≠ automatic transfer of authority to Atlas**

Atlas remains authoritative only within its governed domain.

---

## Signal Layer

Earlier use of **Signal Layer** terminology must not be allowed to collapse several distinct concepts.

The mature Suite distinguishes:

```text
Atlas Signal
≠
Beacon Discovery Signal
≠
legacy trust signal
≠
Attestor Trust Statement
```

Beacon owns:

> **Discovery & Signals**

and its canonical object is:

> **Discovery Signal**

Signal terminology elsewhere must be interpreted by context.

Therefore:

> **A legacy Signal Layer does not create a single Suite-wide signal authority.**

---

## Agent Layer

Legacy Agent Layer terminology may remain relevant as historical or platform context.

It does not create a formal Suite institution.

In particular:

- Aegis does not become a formal Suite institution merely because it operated in an agent-governance context.
- Navigator does not become an Agent Layer authority simply because it orchestrates workflows.
- Attestor does not become agent execution authority merely because it evaluates governed assertions.

Thus:

> **Legacy agent capability ≠ formal Suite institutional authority**

---

## Simulation Layer

Simulation-oriented language may remain part of the wider Satoshium ecosystem where historically or functionally accurate.

It is not one of the eight formal Suite institutions.

Therefore:

```text
Simulation Layer
≠
Formal Suite Institution
```

If simulation functions later become institutionally governed, that would require separate architectural treatment rather than being inferred from legacy terminology.

---

## Interface Layer

Interface or presentation terminology describes how users or systems access Satoshium.

It does not establish authority over the canonical objects being presented.

Therefore:

> **Interface ≠ institutional authority**

A public page, dashboard, API, or presentation layer may expose objects from multiple institutions without owning those objects.

---

## AI Platform Layer

Earlier descriptions of Satoshium as an **AI Platform Layer** may remain historically accurate.

However, that framing is now too narrow to describe the mature Suite.

The current architecture includes:

- independent institutions;
- canonical objects;
- institutional authority;
- lifecycle semantics;
- publication semantics;
- provenance;
- governed interoperability.

Therefore:

> **AI Platform Layer ≠ complete current Suite architecture**

AI remains part of the broader Satoshium ecosystem, but it does not define the full institutional model.

## Aegis Boundary

Aegis remains:

> **External / Pre-Suite**

Current-state Suite architecture must not list Aegis as one of the eight formal institutions.

Therefore:

> **Historical inclusion ≠ current institutional membership**

## Legacy Models That End at Beacon

Some older architecture descriptions may represent the Suite as ending with Beacon.

Those are now stale as current-state descriptions.

The mature formal roster includes:

```text
Attestor
```

as the eighth operational institution.

Therefore:

> **Beacon is not the terminal institution of the completed Suite.**

## Current-State Correction Rule

The reconciliation adopts the following rule:

```text
Historical statement
+ accurate for its date
→ preserve

Current-state statement
+ stale
→ correct

Legacy capability taxonomy
+ still useful
→ preserve with clear framing

Legacy layer terminology
+ implies current institutional authority
→ clarify or correct
```

This avoids both historical rewriting and present-day ambiguity.

## Audit Result

The audit finds no need to redesign the mature Suite.

Instead, legacy layer models should be preserved where historically or conceptually useful while being clearly distinguished from the current formal eight-institution architecture.

No legacy layer should be allowed to override or blur:

- current institutional membership;
- canonical object ownership;
- authority boundaries;
- operational status;
- or the distinction between Aegis and the formal Suite.

---

## Final Disposition

# LEGACY ARCHITECTURE / LAYER AUDIT — COMPLETE — APPROVED

The legacy Trust, Knowledge, Intelligence, Signal, Agent, Simulation, Interface, and AI Platform layer models are preserved as historical or capability-oriented architecture where accurate.

They are not the current formal Suite institutional architecture.

The mature Suite remains:

```text
Atlas
Navigator
Certifier
Registry
Chronicle
Anchor
Beacon
Attestor
```

with Aegis preserved outside the formal Suite.
