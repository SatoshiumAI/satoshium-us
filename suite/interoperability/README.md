**Path:** `/suite/interoperability/`

---

## Purpose

Suite Interoperability defines how independent Satoshium institutions exchange durable references while preserving distinct canonical objects, identifiers, lifecycles, governance, provenance, and authority.

> **Reference does not transfer authority.**

Interoperability connects responsibilities.

It does not merge institutions.

---

## Institutional Model

```text
Atlas      → Authoritative Intelligence
Certifier  → Certification Package
Registry   → SREG
Chronicle  → Chronicle Entry
Anchor     → Integrity Reference
Beacon     → Discovery Signal
Attestor   → Trust Statement
Navigator  → Workflow Definition
```

Discovery Metadata is a supporting Beacon layer rather than a separate canonical object type.

## Structural Distinction

The production object set demonstrates the Suite principle:

```text
Independent canonical objects
+ durable references
+ institution-specific provenance
+ preserved authority boundaries
= interoperable institutions
```

A later-created related object does not automatically require earlier canonical objects to be rewritten.

## Canonical Suite Flow

```text
Atlas provides authoritative intelligence.
Certifier certifies a defined subject.
Registry catalogs authoritative records.
Chronicle preserves qualifying historical Occurrences.
Anchor preserves governed Integrity References.
Beacon publishes Discovery Signals.
Attestor produces Trust Statements.
Navigator orchestrates workflows.
```

Not every institution must participate in every workflow.
