## Governing Rule

> **INTEROPERABILITY REVIEW EXAMINES EXCHANGE MECHANICS; IT DOES NOT REOPEN SETTLED SUITE ARCHITECTURE.**

The review may determine or standardize:

```text
interfaces
reference contracts
serialization
schema compatibility
identifier resolution
handoff mechanics
state propagation
version propagation
exchange constraints
compatibility rules
failure behavior
external-system boundaries
```

The review may not silently redefine:

```text
formal Suite membership
institutional roles
canonical object ownership
authority boundaries
relationship meanings
lifecycle semantics
publication semantics
settled controlled terminology
```

If an interoperability proposal appears to require changing one of those settled architectural matters, it must be escalated explicitly as an architectural conflict rather than normalized as an implementation decision.
