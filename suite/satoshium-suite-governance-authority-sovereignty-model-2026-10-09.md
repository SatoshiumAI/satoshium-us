# II. Suite Governance vs. Institutional Governance

The governing distinction is:

```text
SUITE GOVERNANCE
→ protects the constitutional whole
→ governs shared boundaries
→ governs material cross-institution change
→ protects institutional sovereignty

INSTITUTIONAL GOVERNANCE
→ governs institution-owned responsibilities
→ governs canonical object stewardship
→ governs institution-specific Rules / Policies / Procedures
→ governs operational decisions within settled authority
```

The stop-line is:

> **Suite Governance governs the boundaries that make the Suite coherent. Institutional Governance governs the work that makes each institution operational. Suite Governance must stop where constitutional protection would become operational takeover.**

Therefore:

```text
SUITE CONSTRAINT
≠
SUITE OWNERSHIP

OVERSIGHT
≠
OPERATION
```

```text

→ defines shared implementation principles / repeatable methods

Current Governance Standard
→ governs ownership, change, versioning, review, and preservation of Suite Standards

Institution-Specific Rules
→ define binding requirements inside the institution

Institution-Specific Policies
→ define governed interpretation and operating conditions

Institution-Specific Procedures
→ define repeatable operational execution
```

A simple linear model such as:

```text

↓
Methodology
↓
Governance
↓
Institutions
```

is insufficient.

Governance is not merely another layer in a vertical implementation stack.

It is a control function governing change, accountability, authority, and preservation across the governed surface.
