Satoshium Anchor · Publication

Publication defines when a completed Integrity Reference becomes a publicly authoritative Anchor record and how its human-readable and machine-readable representations remain consistent.

Publication confers public Anchor-record authority only. It does not transfer Source authority, validate substantive truth, or create trust conclusions.

Publication Principle

Publish only what Anchor can preserve, explain, verify, and version.

Public Authority Boundary

Public Anchor Record Authority
≠
Source Artifact Authority

Publication makes Anchor authoritative for the published Integrity Reference, its Version, its integrity metadata, its provenance, and its relationships.

Publication does not make Anchor authoritative for the Source Artifact's substantive meaning.

Reference does not transfer authority.

Publication Preconditions

Before Publication Gate approval, a production Integrity Reference should have:

Anchor Identifier assigned
Anchor Version assigned
Source identity established
Canonical Representation defined
Representation Boundary defined
Integrity Method recorded
Integrity Value / proof material recorded
required Provenance present
required Relationships present
Initial Verification completed
Lifecycle State appropriate
no unresolved blocking Correction

Validation architecture should eventually convert these expectations into explicit institutional checks.

Publication Gate Decision

The Publication Gate should produce a simple institutional decision:

APPROVED
or
NOT APPROVED

The Publication Gate is not a Verification Result and not a Lifecycle State.

Publication Gate Decision ≠ Verification Result ≠ Lifecycle State

Publication Gate Approval

APPROVED means Anchor has determined that the Integrity Reference is ready to enter public institutional use under its current Anchor Version.

Approval does not mean:

Source content is true
Source Artifact is trusted
Certification succeeded
trustworthiness established
future Verification is guaranteed

Publication Gate Rejection

NOT APPROVED means the record is not yet eligible to become publicly authoritative under Anchor.

Potential reasons include:

incomplete schema
unresolved Verification issue
missing provenance
invalid relationship
unresolved Correction
unclear Representation Boundary
missing publication representation
governance hold

Rejection should preserve the draft workflow without creating a misleading production publication event.

Publication Timestamp

Every publicly authoritative Anchor Version should preserve:

published_at

The timestamp should represent the moment the Version entered public Anchor authority, not necessarily the time the Source Artifact was created or the integrity material was generated.

Time Separation

Source creation time
≠ Integrity generation time
≠ Verification time
≠ Publication time

These timestamps answer different institutional questions and should remain separate.

Canonical Human Representation

The canonical HTML page should communicate the same institutional facts expressed by the canonical machine-readable record.

Human presentation may reorganize information for clarity, but it must not contradict the canonical JSON.

Canonical Machine Representation

Canonical JSON should preserve the structured form of the Integrity Reference under the governing Schema Version.

It should be suitable for:

machine validation
relationship resolution
independent Verification
archival preservation
cross-Suite consumption

Canonical vs. Derived Representations

Anchor may produce derived pages, indexes, summaries, mirrors, or discovery surfaces that are not canonical Integrity Reference representations.

Canonical Representation
≠
Derived Presentation

Derived surfaces should point back to the canonical Anchor record.

Canonical URL

Publication should eventually assign stable canonical locations for the current Integrity Reference and its machine-readable representation.

stable Integrity Reference URL
+ canonical JSON URL
+ historical Version access

Exact URL syntax remains unfrozen until the Anchor Identifier syntax is finalized.

Current Version

A stable Anchor Identifier should resolve to the current canonical production Version.

Anchor Identifier
↓
current canonical Anchor Version

Historical Versions should remain directly accessible through explicit Version history.

Historical Version Publication

Version 1 → historical
Version 2 → historical
Version 3 → current canonical

Public presentation should make clear which Version is current without suppressing previous states.

Correction Publication

Current corrected Version
+ Correction notice
+ preserved prior Version

Anchor should not create the false appearance that the corrected value was always the original published value.

Lifecycle Publication Behavior

active → current record
superseded → preserved with supersession notice
withdrawn → preserved with withdrawal notice
archived → preserved with archival notice

Draft records should not appear as publicly authoritative production records.

Withdrawal Does Not Mean Deletion

withdrawn
≠
erased

A withdrawn Integrity Reference should remain historically resolvable unless a separate legal or security requirement prevents public access.

Publication Procedure

1. Complete Integrity Reference construction.
2. Confirm Anchor Identifier and Version.
3. Complete required Validation.
4. Complete Initial Verification.
5. Confirm no blocking Correction or governance hold.
6. Generate canonical HTML and JSON.
7. Confirm human / machine consistency.
8. Apply Publication Gate.
9. Record APPROVED or NOT APPROVED.
10. If approved, assign published_at.
11. Publish canonical representations.
12. Update current-Version resolution and index.
13. Preserve prior Versions and notices.

Publication Principle

Publication should convert a completed Integrity Reference into a durable public Anchor record only after its structure, evidence, and canonical representations are ready for independent review.

Publish only what Anchor can preserve, explain, verify, and version.
Corrections → Versioning → Lifecycle → Verification → Schemas → Back to Anchor →
Public authority should begin only where institutional evidence is ready to endure.
