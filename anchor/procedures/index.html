Anchor · Procedures

Satoshium Anchor · Production Procedures

Production Procedures translate Anchor's institutional architecture into ordered, executable workflows.

The public Procedures page serves as the institutional landing page. Individual procedures are maintained as governed Markdown artifacts unless future operational need justifies separate public pages.

Procedure Principle

Architecture defines what Anchor means.
Procedures define what Anchor does.

Integrity Reference Production Procedure

Creates a new Integrity Reference from Source identification through Canonical Representation, integrity generation, provenance, relationships, Initial Verification, and handoff to Publication.

Defined

Integrity Verification Procedure

Reconstructs the governed representation, reproduces or validates integrity material, compares evidence, records the result, and routes non-match conditions.

Defined

Correction Procedure

Distinguishes Source changes from Anchor-owned errors, preserves prior state, applies the integrity-subject test, Versions same-subject Corrections, and creates new identity where required.

Defined

Publication Procedure

Applies structural review, Initial Verification, human/machine consistency, the formal Publication Gate, publication timestamping, canonical release, and Version preservation.

Defined

Maintenance Procedure

Reviews Source, publication, relationships, methods, algorithms, keys, external commitments, and Reverification outcomes after publication.

Defined

Validation Procedure

A formal Validation Procedure remains deferred until `/anchor/validation/` establishes the final PASS/FAIL institutional rules and sequence.

Procedure Authority

Procedures govern Anchor-owned actions only.

Reference does not transfer authority.

Source Institutions remain authoritative for their Source Artifacts, Source Versions, Source Corrections, and Source lifecycle decisions.

Procedure Discipline

Procedures should be specific enough to execute but should not invent roles, approval bodies, automation permissions, or operational systems before Governance proves they are necessary.

Executable sequence now. Organizational machinery only when needed.

Procedure Records

Future production may prove that procedure executions themselves require structured records or identifiers.

Procedure execution record → possible future object

No Procedure Identifier or execution-record identifier is frozen yet.

First Production Test

The first production Integrity Reference should be treated as a controlled test of these procedures.

Architecture → Procedure → Production → Review → Refine

The goal is not to assume the procedures are perfect before they encounter a real record.
