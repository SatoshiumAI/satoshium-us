Satoshium Anchor Definitions

This page defines the core terminology used by Satoshium Anchor as the Suite institution responsible for durable integrity preservation.

Definitions preserve consistent meaning across Anchor documentation, schemas, procedures, Integrity References, verification, publication, maintenance, and Suite interoperability.

Definition Principle

Anchor terminology should describe integrity precisely without absorbing the authority, meaning, certification, historical interpretation, identity, or trust conclusions of the referenced artifact.

Reference does not transfer authority.

Authoritative Artifact

A record, file, package, publication, statement, dataset, or other governed object whose substantive authority remains with the institution or system that created and maintains it.

Source Institution

The institution or system that owns or maintains the authoritative artifact referenced by Anchor.

Canonical Representation

The exact governed representation of an artifact used to generate or verify an integrity value. It defines what bytes, fields, serialization, or published form are actually being anchored.

Representation Boundary

The explicit scope identifying which artifact representation is covered by an Integrity Reference and which surrounding content, metadata, interface elements, or later changes fall outside that reference.

Integrity Reference

Anchor's canonical operational object. An Integrity Reference preserves the governed integrity information needed to identify a defined artifact representation and support later integrity verification.

Integrity Value

A machine-generated value derived from a defined artifact representation and used to support later integrity comparison or verification.

Cryptographic Digest

A deterministic fixed-length value produced by applying a cryptographic hash function to a defined representation.

Hash Algorithm

The cryptographic function used to generate a digest, together with any governed algorithm identification or Version information required for reproducibility.

Timestamp

A recorded date and time associated with creation, observation, anchoring, publication, verification, or another governed Anchor action.

Temporal Context

The set of governed time-related facts needed to interpret when an Integrity Reference, artifact representation, or verification action existed or occurred.

Signature

Cryptographic signature material associated with a defined artifact representation or Integrity Reference. A signature may support integrity or origin verification but does not by itself transfer institutional authority.

Verification Material

Cryptographic, procedural, or descriptive information needed to reproduce, compare, or validate an Integrity Reference.

Anchoring

The governed Anchor process of creating or recording an Integrity Reference for a defined artifact representation.

Integrity Verification

The process of determining whether a reviewed artifact representation is consistent with the Integrity Reference governing that representation.

Verification Result

The recorded outcome of an Anchor integrity-verification action. It describes integrity comparison, not certification, historical truth, reputation, or trustworthiness.

Integrity State

A governed Anchor state describing the current integrity condition of an Integrity Reference or its relationship to the artifact representation it covers. Final production values should be established only after operational review.

Anchor Identifier

A stable identifier assigned by Anchor to an Anchor-owned Integrity Reference. The final production identifier format remains to be established through the Anchor identifier architecture.

Anchor Version

The preserved version of an Anchor-owned Integrity Reference or representation. Anchor Version remains distinct from the Version of the external authoritative artifact.

Source-System Identifier

An identifier assigned by the external authoritative institution to the artifact referenced by Anchor. It remains external authority and must not be replaced by an Anchor identifier.

Publication State

The Anchor-controlled state describing whether an Integrity Reference has entered, remains in, or has been withdrawn from public production. Final controlled values should be established during production architecture.

Lifecycle State

The Anchor-controlled state describing the institutional condition of an Integrity Reference over time. Lifecycle remains separate from verification, publication, and the lifecycle of the referenced artifact.

Correction

A governed change made to Anchor's own record because Anchor's prior representation, metadata, integrity context, or procedural record was incorrect or materially incomplete.

Maintenance

Post-publication review and upkeep of Anchor-owned records, references, verification context, links, representations, Versions, Corrections, and long-term integrity continuity.

Integrity Preservation

Anchor's continuing institutional function of preserving durable integrity context so a later reviewer can understand and verify the relationship between an Integrity Reference and the artifact representation it covers.

Critical Distinctions

Authoritative Artifact ≠ Integrity Reference
Source-System Identifier ≠ Anchor Identifier
Artifact Version ≠ Anchor Version
Integrity Verification ≠ Certification
Integrity Verification ≠ Chronicle Verification
Integrity State ≠ Publication State ≠ Lifecycle State
Signature ≠ Institutional Authority
Integrity ≠ Truth ≠ Trust

Integrity vs. Truth

Integrity asks whether the reviewed representation corresponds to the representation governed by the Integrity Reference.

It does not determine whether the substantive content is true.

Integrity vs. Certification

Anchor verifies integrity relationships. Certifier performs certification under Suite Standards and Suite Methodology.

Integrity vs. History

Anchor preserves integrity context. Chronicle preserves qualifying historical Occurrences through Chronicle Entries.

Integrity vs. Trust

Anchor may supply integrity evidence useful to later trust evaluation, but Attestor owns Trust Statements and Anchor does not determine trustworthiness.

Anchor terminology exists to preserve precise integrity meaning across implementations without expanding Anchor into certification, identity, reputation, history, discovery, or trust authority.
