Anchor · Anchoring Process

Satoshium Anchor Anchoring Process

The Anchoring Process defines how an authoritative artifact becomes associated with a durable Anchor Integrity Reference.

The process begins with source authority and representation definition, not with hashing. Integrity is meaningful only when Anchor knows exactly what is being referenced and why that representation is stable enough to verify later.

Purpose

The Anchoring Process provides the repeatable institutional path for creating an Integrity Reference without transferring authority away from the system that owns the referenced artifact.

Process Boundary

Anchor does not create the substantive artifact or determine what it means. Anchor begins when a candidate artifact is identified for integrity preservation.

Authority First

Before integrity material is generated, Anchor must identify the Source Institution and confirm which artifact is authoritative for the representation being anchored.

Verification Goal

The process exists so a future reviewer can reproduce or validate integrity material and compare a reviewed representation with the Integrity Reference.

Anchoring Sequence

The production-oriented Anchoring Process follows this institutional path:

Identify Authoritative Artifact → Confirm Source Authority → Define Canonical Representation → Define Representation Boundary → Select Integrity Method → Generate Integrity Value → Record Temporal / Signature / Verification Material → Construct Integrity Reference → Verify Construction → Publish / Preserve → Maintain / Reverify when required

1. Identify Authoritative Artifact

Identify the record, package, file, publication, statement, dataset, or other governed object whose integrity should be preserved.

2. Confirm Source Authority

Confirm the Source Institution, Source-System Identifier where one exists, artifact type, and authority boundary before Anchor creates its own Integrity Reference.

3. Define Canonical Representation

Determine the exact representation that will be processed for integrity, such as canonical JSON, a defined file, a package artifact, or another reproducible representation.

4. Define Representation Boundary

Explicitly identify what content is covered by the Integrity Reference and what surrounding presentation, generated interface, or later state is outside that reference.

5. Select Integrity Method

Select the governed mechanism appropriate for the representation, including the applicable digest algorithm, signature method, timestamp method, external commitment method, or other integrity mechanism.

6. Generate Integrity Value

Generate the Integrity Value from the defined Canonical Representation. A cryptographic digest is the most direct initial example.

7. Record Verification Material

Record the metadata needed to reproduce or validate the integrity result, including algorithm information, timestamps, signatures, representation instructions, and external commitment references where applicable.

8. Construct Integrity Reference

Assemble the Anchor-owned Integrity Reference linking the Source Institution, Source-System Identifier, Canonical Representation, Integrity Value, and required integrity metadata.

9. Verify Construction

Confirm that the Integrity Reference corresponds to the intended artifact representation and that its integrity material can be reproduced or validated before public production use.

10. Publish / Preserve

When the applicable production requirements are satisfied, publish or preserve the Integrity Reference according to Anchor's later-defined Publication and Lifecycle architecture.

11. Maintain / Reverify

Review the Integrity Reference when the Source Artifact changes, a reference breaks, an algorithm becomes unsuitable, verification fails, or later integrity review is institutionally required.

12. Preserve Lineage

Preserve prior material states, Corrections, Versions, verification history, and later Integrity References so the integrity history remains reconstructable over time.

What the Process Produces

The Anchoring Process produces an Anchor-owned Integrity Reference.

Integrity Reference · Source-System Reference · Canonical Representation · Representation Boundary · Integrity Value · Algorithm Metadata · Temporal Context · Signature / Verification Material · Anchor Metadata

The final production schema and required field set remain to be established through Anchor's later schema architecture.

Canonical Representation Comes Before Hashing

A hash is useful only when a later reviewer can determine exactly what representation produced it.

Anchor therefore does not treat:

"Hash this record"

as a sufficient institutional instruction.

The process must first establish:

Which artifact? → Which authoritative source? → Which exact representation? → Which boundary? → Which governed method?

Hashes

Hashing may generate a deterministic Integrity Value for a defined Canonical Representation. Hashing is a mechanism within the process, not the process itself.

Timestamps

Timestamps preserve temporal context and should be labeled by meaning, such as anchoring time, observation time, publication time, or verification time.

Signatures

Signatures may support integrity or origin verification. They do not automatically establish substantive authority, truth, certification, reputation, or trust.

External Commitments

External commitments, including possible future Bitcoin commitments, may strengthen long-term independently reviewable integrity without defining Anchor's institutional identity.

Source Artifact Changes

A Source Artifact may legitimately change after an Integrity Reference is created.

A later Source Artifact Version, Correction, lifecycle change, migration, or new canonical representation does not erase the earlier integrity relationship.

Preserve which representation was anchored, which Integrity Reference covered it, and how later representations relate to that state.

Verification After Anchoring

Later Integrity Verification begins with the preserved Integrity Reference and the artifact representation under review.

Integrity Reference + Reviewed Representation → Reproduce / Validate Integrity Material → Compare → Verification Result

A match supports integrity consistency. A mismatch requires investigation.

A mismatch does not automatically establish tampering, wrongdoing, falsity, or loss of institutional authority.

Authority Boundary

Anchor owns the Integrity Reference.

The Source Institution continues to own the authoritative artifact and its substantive status, meaning, certification, historical interpretation, or trust context.

Reference does not transfer authority.

Process Philosophy

Anchoring is not a declaration of truth. It is the governed creation of a durable integrity relationship between an Anchor Integrity Reference and a defined artifact representation.

The process should remain reproducible, reviewable, implementation-neutral, and minimal enough to preserve integrity without duplicating the authoritative record.

Define the representation. Generate the integrity evidence. Preserve the reference. Make later verification possible.
